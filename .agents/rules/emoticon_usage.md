# Emoticon & Emoji Usage Policy

## 1. Core Rule
**Knock off emoticons and emojis across all aspects of the project.**

- Do **not** use emoticons or Unicode emojis as routine decoration, conversational filler, list bullets, or section badges.
- **Allowed Exception:** Emoticons/emojis may only be used **VERY sparingly for great effect** when they serve a clear, functional purpose. In ordinary workflows, default to zero emojis.

## 2. The Distinction: Functional UI Mapping vs. Gratuitous Decoration

### Great (Allowed — High Functional Value):
Visual UI iconography references where the emoji directly depicts an actual on-screen software element that students must visually locate and click in their editor or browser:
- `Activity Bar (Far Left): Access the File Explorer (📁), Search (🔍), Git Source Control (🔀), and the SQLTools Database Manager (stacked cylinder icon).`
Here, the folder, magnifying glass, and branch icons visually match what the student literally sees on their screen.

### Not Allowed (Prohibited — Gratuitous Decoration):
Decorative or whimsical emojis attached to headings, bullets, callouts, or chat responses:
- `✨ Auto-Formatting Code`
- `🚀 Step 1: Create Your Personal Student Repository`
- `💡 Conserving Cloud Hours`
- `📝 5-Step Weekly Lab Submission Workflow`
- `🎉 Great job!` or `✅ Done!` in assistant responses

## 3. Scope of Enforcement
1. **Assistant Communications:** Responses must remain clean, direct, and professional without decorative emojis.
2. **Canvas Course Content & Wiki Pages:** Headings, panel titles, accordions, and text blocks use clean typography, numbers, and semantic HTML or DesignPLUS FontAwesome icons (`<i class="fas fa-..."></i>`) instead of Unicode emojis.
3. **Course Documentation & Markdown:** Standard technical writing style without decorative emoji prefixes.
4. **Code & Build Scripts:** Clean comments, terminal logs, and commit messages.
